## Push the claim to origin/main BEFORE opening a worktree (required, A-039)
`origin/main` is the only place a claim counts. From your current checkout:

    git fetch origin
    ./scripts/assignment-status.sh   # re-check: still claimable on origin/main?
    git add docs/assignments/QUEUE.md docs/assignments/INDEX.md docs/SESSION.md
    git commit -m "docs: claim A-NNN on main before opening worktree"
    git push origin main

If the push is rejected, `git fetch && git pull --ff-only`, re-check, and either
retry or pick a different claimable id — never force-push over another claim.

## Land on main before you stop (required)
Leaving finished work only on a feature branch causes forgotten merges, conflicts, and wasted tokens.

After your batch is accepted (default: one assignment):
1. Run `./scripts/test-smoke.sh` by default; `./scripts/test-full.sh` before this merge, or if you touched `brain`/`overlay`/`actions` (A-040/ADR-039). Never paste `-v`/full output — quote only the printed `FAIL:`/`ERROR:` lines.
2. Ensure QUEUE/INDEX/SESSION/PROGRESS for this work are correct on **this branch**, then push the branch with `git push -u origin HEAD`.
3. **Merge into `main` and push `main`** before reporting done:
   - Preferred: create a PR with `gh pr create --title "..." --body "..."` if needed, then `gh pr merge --merge` (or squash if that is the repo norm), then `git fetch origin && git checkout main && git pull`.
   - If PRs are not required / you have push access: merge your branch into local `main`, resolve bookkeeping conflicts without wiping other claims, then `git push origin main`.
4. Reconcile shared bookkeeping on **main** so the next CONTINUE sees `done` / released claims (same spirit as cross-worktree claim visibility).
5. Only then remove your worktree/branch per START cleanup rules.
6. Your final report to Alex must include: merged yes/no, PR URL if any, and confirmation that `origin/main` has the update.

If merge is blocked (permissions, failed checks, conflicts you cannot safely resolve): open/update the PR, say **BLOCKED ON MERGE**, and do not claim you finished landing.

## After merge: remove worktree and return to main (required)
Before you stop **or** claim another assignment / take a new CONTINUE prompt:
1. Confirm your work is on `origin/main` (merged).
2. From a remaining checkout (usually the canonical tree), remove **your** finished worktree and delete the merged branch (never force; never touch another agent's tree):

```bash
git -C "$HOME/Work/omarchy-jarvis-<your-slug>" status --short
git worktree remove "$HOME/Work/omarchy-jarvis-<your-slug>"
git branch -d <your-branch>
```

3. `cd` back to the canonical checkout and update main:

```bash
cd "$HOME/Work/omarchy-jarvis"
git checkout main
git pull origin main
```

4. Only then stop and report — or, if Batch allows another assignment, claim the next one **from this updated `main`** (new worktree for the new assignment). Do not start the next prompt while still sitting in the old feature worktree.

Remove only clean, merged, unowned trees; never force. Default batch size is 1 unless Alex explicitly enabled more.

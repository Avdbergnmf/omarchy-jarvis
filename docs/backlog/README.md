# Backlog — how to triage

Jarvis self-improves **through you**, not around you: it files rich records, it does not silently fix itself. Every bug/miss and feature request Jarvis reports lands here (and, unless filing failed, as a GitHub issue in `Avdbergnmf/omarchy-jarvis`). Not every issue is insta-solved — **credits are scarce**, so the point is to file well now and batch-fix later on whichever agent has budget.

## Where things live
```
docs/backlog/
  README.md          # this file
  INDEX.md            # id | type | title | difficulty | status | gh issue — updated by report_bug/report_feature
  bugs/<slug>.md       # local mirror of filed bugs
  features/<slug>.md   # local mirror of filed features (required by design)
  handoffs/active/issue-<n>-<agent>.md   # paste-ready prompts generated by prepare_handoff
docs/templates/
  ISSUE_BUG.md ISSUE_FEATURE.md HANDOFF_AGENT.md
```

## Difficulty legend
| Difficulty | Meaning | Example |
|---|---|---|
| **S** | Docs/UI copy, one file, no new behavior | Fix a typo, clarify a message |
| **M** | One action/skill, contained change | New action, bugfix in `actions/` or `overlay/` |
| **L** | Architecture, multi-agent, cross-cutting | New control-plane state, model swap |

## Agent routing guide
Difficulty is a **suggestion**, not an auto-dispatch. Jarvis never spends another agent's credits without your explicit approval of a real send (see below).

| Difficulty | Suggested solver | Why |
|---|---|---|
| S | local docs fix, or you | Not worth spinning up an agent |
| M | Claude Code (Sonnet) on this repo | Contained, well-scoped, cheap |
| L / cross-cutting | Opus or a Cursor cloud agent, when credits allow | Needs more context/budget |

Never assume Firsty or another chat agent was messaged unless you explicitly commanded a real send and a connector exists for it. As of this pass, no such connector is wired up — `prepare_handoff` only **writes a local prompt file**; nothing is sent anywhere.

## How to use this from the overlay
- `/report <what went wrong>` or say "you messed up …" → bug intake
- `/feature <what you want>` or say "add a feature …" / "I wish it could …" → feature intake
- Jarvis asks up to 3 short clarifying questions, one at a time. Reply **`skip`** any time to file with what it already has.
- The draft issue (title, labels, body) is shown before anything is filed — **Run** files it via `gh issue create`, **Cancel** files nothing.
- `/backlog` lists open bugs/features from GitHub plus this INDEX.
- `/dispatch <issue> to <agent>` (agent = `claude-code` | `cursor` | `human`) **prepares** a handoff prompt file; it never contacts or charges another agent on its own — no real-send hook exists in this pass, at all, for any agent. If one is ever added, it must be gated behind explicit approval and a `dispatch.enabled = false`-by-default key in `~/.config/jarvis/config.toml`, same convention as `approval_mode`/`show_notifications`.

## Triage checklist
1. Read the issue/local mirror; the context pack should let you understand the miss/request without the original chat.
2. Confirm suspected layer and acceptance criteria still make sense.
3. Pick a solver using the table above, or leave for later — the backlog is fine sitting untouched.
4. If dispatching, run `/dispatch <issue> to <agent>` and paste the generated file into that agent's chat yourself.
